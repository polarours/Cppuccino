# 02 Intermediate

这个阶段面向已经掌握基础 C++ 语法、类、函数、引用和常用标准库容器的学习者。
接下来的重点不再是“继续背更多语法点”，而是把已有语言知识真正落到设计和工程判断上。

这里的目标，是让所有权、生命周期、错误处理、接口边界、并发模型这些问题，
在小而真实的项目里变得可见。

## 这个阶段主要训练什么

- 把语言语义落实到 API 和模块边界上
- 明确表达所有权与生命周期假设
- 学会管理内存之外的资源
- 在足够小、但又值得重构的项目里练手
- 面对未完成系统时，学会循序渐进地扩展它

## 这个阶段不打算做什么

- 不是生产级系统课程
- 不是完整的网络、存储或操作系统课程
- 不是在设计尚未清晰前就追求极致性能
- 不是展示“已经完全做完”的成品项目

这个阶段刻意采用项目驱动的方式。
部分项目就是故意保留为未完成状态，
因为学习重点本来就是：先看清现状，再有意识地补上缺失部分。

## 项目

### [tiny-http-server](tiny-http-server/README.md)

状态：
已实现为一个最小但完整的 intermediate 练习项目

它主要练什么：

- socket 生命周期与资源管理
- 请求解析边界
- 路由与响应构造
- 固定大小线程池的基础模型
- 传输层、解析层、分发层的职责拆分

它不打算解决什么：

- 不打算实现完整 HTTP 服务器
- 不覆盖长连接、流式处理或生产级加固
- 不在语义边界还不稳定时过早做性能优化

### [key-value-store](key-value-store/README.md)

状态：
规划中，当前尚未实现

它主要练什么：

- 更长生命周期服务中的数据所有权
- 持久化格式设计
- 读写 API 的契约表达
- 同步与一致性的工程权衡
- 有状态系统的测试方式

它不打算解决什么：

- 不去和真实数据库竞争
- 不用模糊接口掩盖底层存储语义
- 不直接跳到分布式系统层面

## 建议的工作方式

面对这个阶段的每个项目，建议固定按这个顺序推进：

1. 先写出所有权边界。
2. 先声明非目标，再继续加功能。
3. 一次只补一个能力。
4. 控制规模，让实现、测试和文档始终能对齐。

## 当前方向

现在的 `tiny-http-server` 已经可以作为主要练手项目继续往下推进。
`key-value-store` 则是下一步需要认真设计的 intermediate 项目。

这其实是一个不错的状态。
一个项目负责提供可读、可改的真实代码，
另一个项目则保留足够空间，让你可以先把设计做对，再去实现。
