# 中文发布文案 — v1.0.0

## 一句话

Cppuccino 是一个中英双语的 C++ 笔记本：读懂一个想法，复现一个真实失败，
修好它，再证明它。

## V2EX

**标题**

`做了一个双语的 C++ 学习仓库，把未定义行为做成了四个可以打的 Boss`

**正文**

做这个仓库的起因很简单：大部分 C++ 资料把正确路径讲得很清楚，但真正花时间
的地方是失败——对象已经释放、迭代器在派发中被改掉、数据竞争只在负载下出现、
所有权不清楚导致重复释放。

所以我把笔记整理成了一个循环：读概念、复现失败、修代码、过证明。现在仓库里有
140 篇概念文章（中英各 70）、74 篇陷阱文章、161 个可运行示例、151 个小项目，
975 个测试在 CI 里跑。

好玩的层是一个街机：四个 Boss 分别对应生命周期、容器、并发和所有权四类未定义
行为，失败日志来自真实的 ASan / `_GLIBCXX_DEBUG` / TSan 输出，不是编的。UB
训练营把「读 → 实验 → 打 Boss → Proof Gate」串起来，Proof Gate 要每个 Boss
答对三题才算结业。

想听两类反馈：

1. 这种「先看失败再修」的结构对学习有没有帮助，还是反而绕？
2. 哪些解释对已经会 C++ 的人仍然不够准确？

站点是静态的，没有账号、没有统计脚本；中文用系统 CJK 字体，字体自托管，不依赖
Google Fonts。

## 知乎

**标题**

`为什么我把 C++ 的未定义行为做成了 Boss 战`

**正文**

C++ 的难点往往不是语法，而是「这段代码为什么会在某个时刻坏掉」。悬垂指针、
迭代器失效、数据竞争、重复释放，这四类问题在教程里经常只出现一行警告，在真实
项目里却要花几个小时定位。

Cppuccino 是我整理的一套双语 C++ 笔记。它不只讲概念，还给每个概念配一个失败
模式和一个可运行修复。仓库里有 140 篇概念、74 篇陷阱、161 个示例和 151 个项目；
CI 会编译项目并跑 975 个测试。

街机是可选的学习层。四个 Boss 的失败日志来自真实的 sanitizer 输出；Proof Gate
不是读完就送徽章，而是要求每个 Boss 答对三题。这样做不是为了游戏化而游戏化，
而是把「看懂」和「能修」分开。

如果你也在学 C++，欢迎从「未定义行为」或「悬垂指针」开始，也欢迎指出不准确的
地方。项目地址和 Release 都在仓库首页。

## 不要写

- 「最好的 C++ 学习方式」。
- 没有实测依据的「快 10 倍」或性能数字。
- 没有统计依据的「几千用户」或 star 数。
- 把「AI 生成」当卖点；价值在可验证的内容和可复现的失败。
