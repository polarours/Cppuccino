**Text**

I built Cppuccino because most C++ learning material shows the happy path. The
parts that actually cost me time were the failures: a pointer that outlives its
object, an iterator invalidated during dispatch, a data race that only appears
under load, a double free hidden behind ownership.

Cppuccino is an attempt to make those failures the lesson. Every idea has an
English and a Chinese version, a runnable example, and a failure-mode article.
The repository currently contains 140 concept articles, 74 pitfall articles,
161 compiled examples and 151 small projects. The 975 tests run in CI.

The playful part is an arcade. Four boss fights are built around four classes of
undefined behavior, and the failure logs come from real sanitizer runs rather
than invented error text. The UB Training Camp chains read → reproduce → repair
→ prove, and the Proof Gate asks three questions per boss. There is also a
small lifetime lab and three browser experiments embedded in the articles.

I would especially value feedback on:

1. Is the read → break → repair → prove loop useful, or does it get in the way?
2. Are the explanations accurate enough for someone who already knows C++?
3. Which pitfall should be turned into the next interactive lab?

The site is static, has no account system and sends no analytics. Chinese pages
use the reader's system CJK font; fonts are self-hosted so the site does not
depend on Google Fonts.

## First comment (post immediately after submitting)

A few implementation notes, since “learning arcade” can sound like a gimmick:

- The articles and the arcade read from one source tree; the quest list is
  generated from the real Markdown, not maintained by hand.
- A boss cannot mark itself cleared. PROVE is a separate Proof Gate; it only
  completes after 3/3 answers.
- Every example is compiled and run in CI. The browser boss fights use a small
  constrained lifetime DSL, and the page says explicitly that it cannot compile
  arbitrary C++; the real source is linked next to it.
- The site is MkDocs Material with a static overlay for Play mode. No SPA, no
  backend, no cookies.

If something is wrong, the most useful issue includes the compiler, standard,
platform and a minimal reproduction. Security reports should use SECURITY.md,
not the public tracker.

**Body**

I have been collecting C++ notes for a while and kept noticing that the
interesting part was rarely the definition. It was the failure: lifetime,
iterator invalidation, races, ownership. So I turned the notes into a loop:
read the idea, reproduce the failure, repair it, prove it.

The repo has 140 concept articles in English and Chinese, 74 failure-mode
articles, 161 runnable examples and 151 small projects. CI builds the projects
and runs 975 tests. The arcade is an optional layer on top: four boss fights
based on real sanitizer output, plus a four-stop UB Training Camp.

I am not claiming it replaces a book or a compiler. I am curious whether the
failure-first structure helps other people learn, and which parts are still too
hand-wavy. Happy to answer questions about the build or the CI setup.
