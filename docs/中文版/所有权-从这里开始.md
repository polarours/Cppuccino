# 所有权 — 从这里开始

## C++ 中对象生命周期责任起点
> 在 C++ 中，几乎所有复杂问题最终都会归结为一个问题：
> "这个对象由谁负责？"

本文不试图回答"如何写代码"，而是解释 C++ 中的**所有权**是什么，以及为什么它很重要。

## 为什么要讨论所有权？

在学习 C++ 的过程中，我们经常遇到这些问题：
- 这个对象需要 `delete` 吗？
- 析构函数什么时候被调用？
- 这个指针可以传递出去吗？
- 为什么 `move` 之后对象"可以用但不应该用"？
- 为什么 `shared_ptr` 有性能问题？
- 为什么 `const` 不能解决并发安全？

这些问题的根源往往与"谁负责对象的生命周期"有关。理解所有权能帮助我们写出更安全、更高效的代码。

> C++ 没有名为 `ownership` 的关键字，但所有权贯穿于 C++ 的设计理念和实践中。理解所有权能帮助我们更好地理解 C++ 的内存管理、资源管理和并发模型。

## 什么是所有权？

在 C++ 的语境中，所有权不是一个语法概念，而是一种责任关系。

更具体地说，所有权意味着：
- 决定对象何时**创建**、何时**销毁**
- 确保对象在**使用**时有效
- 避免对象被**重复销毁**

> 谁负责对象的生命周期，谁就拥有它。
> C++ 不会为你管理所有权，而是通过其类型系统强制你明确责任。

## 所有权的深入分析

### 所有权的类型

在 C++ 中，所有权可以分为以下几种类型：
- **独占所有权**：任何时刻，一个资源只允许有一个拥有者，生命周期的责任唯一且清晰。
典型代表是 `std::unique_ptr`，也是 C++ 中最推荐的默认所有权形式。
- **共享所有权**：多个对象共同承担资源的生命周期责任，当最后一个拥有者释放时资源才被销毁。
典型代表是 `std::shared_ptr`，通常在无法明确唯一拥有者的场景下使用。
- **非拥有观察**：访问一个资源并不意味着拥有其生命周期，也不参与资源销毁的决策。
常见形式包括裸指针、引用和 `std::weak_ptr`（后者用于观察共享所有权对象）。
- **作用域绑定所有权**：资源的生命周期直接绑定到一个作用域，进入作用域时构造，离开时销毁。
这是 `RAII` 的基本形式，广泛存在于栈对象和本地资源管理中。
- **所有权转移**：资源生命周期的责任可以在对象间显式转移，通常通过移动语义实现。
这是现代 C++ API 设计中的核心能力。
- **资源所有权**：所有权不仅限于内存，还包括文件、互斥锁、套接字等系统资源。
`RAII` 的真正价值往往体现在对这些资源的管理中。

> 需要注意的是，上述分类并非在语言层面强制性定义，而是对 C++ 工程实践中常见所有权语义的抽象总结。
> 在工程实践中，一条非常重要的经验法则是：**优先使用独占所有权，仅在无法明确唯一拥有者时才考虑共享所有权。**
> 在复杂系统中，还会以更多结构性或上下文相关的所有权形式出现，后续章节将逐步讨论。

### 所有权与生命周期

理解所有权需要理解对象生命周期。生命周期包括：
- **创建**：对象被分配内存并初始化。
- **使用**：对象在有效期内被访问。
- **销毁**：对象的资源被释放，析构函数被调用。

所有权决定了对象生命周期的各个阶段：谁负责创建、谁负责销毁、谁可以在有效期内使用。

## 所有权的最佳实践

### 1. 优先使用独占所有权

```cpp
std::unique_ptr<int> p = std::make_unique<int>(42);
```

`std::unique_ptr` 是最安全、最高效的所有权形式。它明确表示"我拥有这个对象"，并且阻止了意外的共享。

### 2. 非拥有引用使用 std::string_view

```cpp
void process(std::string_view data);
```

`std::string_view` 提供了非拥有的字符串访问，避免了不必要的拷贝。

### 3. 避免裸指针所有权

```cpp
// 不推荐：裸指针的所有权不明确
int* p = new int(42);

// 推荐：使用智能指针明确所有权
auto p = std::make_unique<int>(42);
```

### 4. 明确接口的所有权语义

```cpp
// 返回 unique_ptr：所有权转移
std::unique_ptr<Foo> createFoo();

// 返回 const reference：非拥有观察
const Foo& getFoo();

// 接受 unique_ptr 的转移：所有权获取
void takeOwnership(std::unique_ptr<Foo> foo);
```

## 所有权与 RAII

RAII（Resource Acquisition Is Initialization）是 C++ 中所有权管理的核心模式。其核心思想是：

> **资源的生命周期与对象的生命周期绑定。**

```cpp
class FileHandle {
    std::FILE* fp_;
public:
    explicit FileHandle(const char* filename) : fp_(std::fopen(filename, "r")) {}
    ~FileHandle() { if (fp_) std::fclose(fp_); }
    // 禁止拷贝，允许移动
    FileHandle(const FileHandle&) = delete;
    FileHandle& operator=(const FileHandle&) = delete;
    FileHandle(FileHandle&&) = default;
    FileHandle& operator=(FileHandle&&) = default;
};
```

通过 RAII，我们可以将资源管理转化为对象管理，利用构造和析构函数自动管理资源的生命周期。

## 所有权与并发

所有权在并发编程中尤为重要：

### 线程所有权

当一个对象被传递到另一个线程时，所有权需要明确转移：

```cpp
void worker(std::unique_ptr<Data> data);
std::thread t(worker, std::make_unique<Data>(...));
t.join();
```

### 共享所有权

当多个线程需要访问同一对象时，考虑使用共享所有权：

```cpp
std::shared_ptr<Data> sharedData = std::make_shared<Data>();
std::thread t1([](std::shared_ptr<Data> d) { /* ... */ }, sharedData);
std::thread t2([](std::shared_ptr<Data> d) { /* ... */ }, sharedData);
```

## 总结

所有权是 C++ 的核心概念，理解所有权能帮助我们：
- 写出更安全、更清晰的代码
- 避免常见的内存错误
- 更好地设计 API 接口
- 更有效地管理资源

> **记住：谁负责，谁拥有。所有权不明确的地方，就是 Bug 潜伏的地方。**
