# 从值类别到引用绑定（From Value Categories to Reference Binding）

> 关于值类别的各种资料大家都可以在网上找到，本文尽量能够系统、深入地解释值类别的概念与演变，帮助读者建立对 C++ 值类别的全面理解。

## 1. 引言

### 1.1 值类别存在的背景与意义

在 C++ 中，我们习惯从“类型（type）”的角度理解程序：

```cpp
int x = 0;
```

但仅仅知道 `x` 的类型是 `int`，**并不足以描述 `x` 在表达式中的全部语义**。

例如：

```cpp
x;        // 一个表达式
x + 1;    // 另一个表达式
```

这两个表达式的类型都与 `int` 有关，但它们在语言层面的“性质”完全不同。

C++ 引入**值类别（value categories）**，正是为了回答这样一个问题：

> **当一个表达式被求值时，编译器应该如何理解“这个结果”？**

### 1.2 表达式、对象与结果

在深入值类别之前，必须区分三个经常被混淆的概念：

- 表达式（expression）
- 对象（object）
- 表达式的求值结果

#### 1.2.1 表达式不等于对象

```cpp
int x = 1;
x + 2;
```

`x + 2` 是一个合法的表达式，但它并不 **“声明”** 或 **“命名”** 任何对象。

表达式只是**一段语义规则**，描述如何计算一个结果。

#### 1.2.2 求值结果也不一定是对象

表达式求值后，可能得到：

- 一个已有对象
- 一个临时对象
- 一个纯计算结果（不具备对象身份）

例如：

```cpp
x;        // 求值结果是已有对象 x
x + 2;    // 求值结果是一个临时计算结果（非对象）
```

值类别正是用来区分这些情况的。

### 1.3 对象身份（Identity）：值类别的核心

现代 C++ 中，区分值类别的**根本标准**是：

> **表达式的结果是否具有对象身份（identity）？**

可以用一个直观的问题来判断：

> “这个结果，是不是某一个‘可以再次识别出来’的对象？”

#### 1.3.1 有身份的结果

如果一个表达式的结果：

- 可以区分“是不是同一个实例”
- 语义上对应某段存储

那么它就**具有 identity**。

```cpp
int x = 0;
x;      // 具有身份
```

#### 1.3.2 没有身份的结果

如果一个结果只是“算出来的值”，而不标识任何对象：

```cpp
x + 1;  // 不具有身份
```

那么它在语义上就**不具备 identity**。

## 2. 值类别的演变与分类

### 2.1 C++ 中值类别的发展

在 早期的 C++ （C++ 98 / 03） 中，值类别主要分为**左值（lvalue）**和**右值（rvalue）**两大类。

- **左值（lvalue）**：最早表示出现在赋值号左侧并且可以被赋值的对象。后来扩展为表示具有身份标识（identity）的对象，可以通过引用（reference）来访问和修改。
- **右值（rvalue）**：表示临时对象或字面值（literal），没有身份标识，通常出现在赋值号右侧，不能被引用。

一直到 C++11 引入了**右值引用（rvalue references）**和**移动语义（move semantics）**，左值和右值的定义变得更加复杂。C++11 对值类别进行了扩展，现在的左值和右值被进一步细分为以下几类：

- **左值（lvalue）**：可以长期存在的对象，具有身份标识。分配有实际的内存地址。
- **右值（rvalue）**：临时对象或字面值，没有身份标识。分配在临时存储区，生命周期短暂。
- **将亡值（xvalue）**：一种特殊的右值，具有标识，并且可以移动。表示即将被销毁的对象，其资源可以被转移，可以被多态。
- **纯右值（prvalue）**：表示临时计算结果，没有身份标识，不能被移动，不能被多态。
- **广义左值（glvalue）**：包括左值和将亡值，表示具有身份标识的对象。

### 2.2 为什么要扩展值类别？

在 C++98/03 时代，只有 `lvalue` 和 `rvalue` 两种分类，造成编译器无法区分“命名对象”和“即将销毁的临时对象”，导致即使是临时对象，也只能拷贝，不能“迁移”资源。

这直接限制了高效资源管理的能力。例如：

```cpp
std::string s1 = "hello";               // 拷贝构造
std::string s2 = std::string("world");  // 还是拷贝构造，即使是临时对象
```

C++11 通过引入 `xvalue` 和 `prvalue` 的细分，彻底改变了局面，扩展后，编译器才能实现：

- 移动构造函数 / 移动赋值运算符
- 完美转发（perfect forwarding）
- 保证拷贝消除（guaranteed copy elision）
- 更智能的临时对象生命周期管理

> 如果有不理解的地方，没关系，这些我们后面会逐步展开讲解。

## 3. 深入理解值类别

在本章节，我们着重讲解三种主要的值类别：**左值（lvalue）**、**将亡值（xvalue）**和**纯右值（prvalue）**。

### 3.1 左值（lvalue）

`lvalue` 是最直观、最常见的一类值类别。它表示具有 **身份标识（identity）** 的对象，可以通过引用访问和修改。

在 C++ 中，`lvalue` 的定义简单的说就是：

> `lvalue` 是“有名字、有地址、可以反复使用的对象”**。

#### 3.1.1 常见的 `lvalue`

##### Ⅰ. 命名变量

```cpp
int x = 42;     // x 是一个 lvalue
x = x + 1;      // 可以通过 x 访问和修改其值
```

##### Ⅱ. 解引用指针

```cpp
int* p = &x;    // p 是一个指向 x 的指针
*p = 100;       // *p 是一个 lvalue，可以修改 x 的值
```

##### Ⅲ. 函数返回左值引用

```cpp
int& getRef(int& a) {
    return a;    // 返回一个 lvalue 引用
}

int y = 10;
getRef(y) = 20; // 可以通过返回的引用修改 y 的值
```

##### Ⅳ. 数组元素

```cpp
int arr[3] = {1, 2, 3};
arr[0] = 10;    // arr[0] 是一个 lvalue，可以修改数组元素
```

##### Ⅴ. 类成员变量

```cpp
class MyClass {
public:
    int member;
};

MyClass obj;
obj.member = 5; // obj.member 是一个 lvalue，可以修改成员变量
```

##### Ⅵ. 字符串字面值（C 风格字符串）

```cpp
char* str = "Hello";
str[0] = 'h'; // str[0] 是一个 lvalue
```

字符串字面值 "Hello" 本身是 `const char[]` 类型，数组名退化为了指针 `char*`，因此 `str[0]` 是一个 lvalue，可以通过它修改字符串内容（尽管这种做法是不安全的，现代 C++ 应该使用 `std::string`）。

#### 3.1.2 `lvalue` 的关键属性

| 属性 | 描述 | 含义 |
| --- | --- | --- |
有身份（identity） | 是（有持久存储、可被多次引用） | 可以安全绑定非 const 左值引用
可取地址（&）？ | 是（除函数名、位域等特殊情况） | 常用 & 操作符取地址
默认行为 | 拷贝（不能直接移动） | 传递大对象时需显式 std::move
可赋值左侧？ | 是（非 const lvalue） | 支持修改
生命周期 | 由声明决定（自动、静态、动态） | 通常最安全，但拷贝开销可能大

#### 3.1.3 `lvalue` 在引用绑定中的行为

- 可以绑定到 `T&` 和 `const T&`
- 不能直接绑定到 `T&&`（除非通过 `std::move` 转为 `xvalue`）

```cpp
int x = 42;
int& lr = x;           // OK
const int& clr = x;    // OK

// int&& rr = x;       // 错误！lvalue 不能直接绑定右值引用
int&& rr = std::move(x);  // OK，std::move 把 lvalue 转为 xvalue
```

> 关于 std::move 的更多内容，请参考后续章节。

### 3.2 纯右值（prvalue）

纯右值是“最纯粹的临时”类别，没有身份标识，纯粹是计算结果或初始化用的临时对象。

一句话总结就是：

> 一个表达式，如果其求值用于初始化一个对象或作为操作数的值，且没有指定任何已有对象，则是 prvalue。

#### 3.2.1 常见的 `prvalue`

##### Ⅰ. 字面值常量

```cpp
int a = 42;          // 42 是一个 prvalue
double pi = 3.14;    // 3.14 是一个 prvalue
```

##### Ⅱ. 临时对象

```cpp
std::string s = std::string("hello"); // std::string("hello") 是一个 prvalue
```

##### Ⅲ. 非引用返回的函数调用

```cpp
int getValue() {
    return 100; // 返回的 100 是一个 prvalue
}
int val = getValue(); // getValue() 是一个 prvalue，val 是 lvalue
```

##### Ⅳ. lambda 表达式

```cpp
auto lambda = []() { return 42; }; // lambda 是一个 prvalue
int result = lambda();              // lambda() 是一个 prvalue
```

##### Ⅴ. 算术和逻辑表达式

```cpp
int sum = 1 + 2;        // (1 + 2) 是一个 prvalue
bool flag = (a == b);     // (a == b) 是一个 prvalue
```

#### 3.3.2 `prvalue` 的关键属性

| 属性 | 描述 | 含义
| --- | --- | --- |
有身份（identity） | 否 | 不可多次引用
可取地址（&）？ | 否 | &42 非法
可被移动？ | 是（默认） | 支持移动构造
生命周期 | 非常短暂（表达式结束即销毁） | 需绑定引用来延长
默认行为 | 拷贝消除（C++17+ guaranteed）或移动/拷贝 | 最高效的临时处理

#### 3.3.3 `prvalue` 在引用绑定中的行为

- 可以绑定到 `const T&`（延长生命周期）
- 可以绑定到 `T&&`（触发移动）
- 不能绑定到 `T&`

```cpp
int&& rr = 1024;          // OK，42 是 prvalue，可以绑定到右值引用
const int& cr = 1024;     // OK，42 是 prvalue，可以绑定到常量左值引用
// int& lr = 1024;        // 错误！prvalue 不能绑定到非常量左值引用
```
### 3.3 将亡值（xvalue）

将亡值（xvalue，expiring value）是 C++11 引入的值类别。它是**唯一同时属于 glvalue（有身份）和 rvalue（可移动）的类别**，专门为了解决“命名对象也能被移动”的需求而设计。

一句话总结：
> 一个表达式，如果其求值结果指定了一个**具有身份的对象**，但该对象**即将被销毁**（其资源可以被重用），则该表达式是 xvalue。

#### 3.3.1 常见的 `xvalue`

##### Ⅰ. 使用 `std::move` 转换的对象

`std::move` 可以将一个左值转换为将亡值，从而允许移动语义的发生。

> 移动语义简单的说就是“允许资源从一个对象转移到另一个对象，而不是拷贝”。

```cpp
int x = 42;
int&& rr = std::move(x); // std::move(x) 是一个 xvalue
```

##### Ⅱ. static_cast<T&&> 和 reinterpret_cast<T&&>

```cpp
int x = 42;
int&& rr_1 = static_cast<int&&>(x); // static_cast<int&&>(x) 是一个 xvalue
int&& rr_2 = reinterpret_cast<int&&>(x); // reinterpret_cast<int&&>(x) 也是一个 xvalue
```

- `static_cast<T&&>` 是 C++ 引用绑定和移动语义体系里合法、安全地改变表达式值类别的手段。
- `reinterpret_cast<T&&>` 是一种特殊的转换方式，更像是一个编译器指令，通常不推荐使用。

##### Ⅲ. 当对象本身是 `xvalue` 时，其成员访问也是 `xvalue`

```cpp
class MyClass {
public:
    std::string name;
};

MyClass obj;
std::string&& nameRvalue = std::move(obj).name; // std::move(obj).name 是一个 xvalue
```

#### 3.2.2 `xvalue` 的关键属性

| 属性 | 描述 | 与 `lvalue`/`prvalue` 的区别 | 含义 |
| --- | --- | --- | --- |
有身份（identity） | 是（有地址、可多次引用） | 与 `lvalue` 相同，与 `prvalue` 不同 | 可以被再次访问，但通常不推荐
可取地址（&）？ | 是 | 与 `lvalue` 相同 | &std::move(x) 是合法的
可被移动？ | 是（设计目的就是允许移动） | 与 `prvalue` 相同，与 `lvalue` 不同 | 触发移动构造函数/赋值
生命周期 | 即将结束（full-expression 末尾） | 比 `lvalue` 短，比 `prvalue` 稍长 | 使用后原对象进入“已移动”状态
默认行为 | 移动 | — | 资源转移的桥梁

#### 3.2.3 `xvalue` 在引用绑定中的行为

- 可以绑定到 `T&&`（右值引用） → 触发移动
- 可以绑定到 `const T&`（临时延长生命周期）
- 不能直接绑定到 `T&`（非 const 左值引用）

```cpp
int x = 42;
int&& rr = std::move(x);          // OK，xvalue 可以绑定到右值引用
const int& cr = std::move(x);     // OK，xvalue 可以绑定到常量左值引用
// int& lr = std::move(x);        // 错误！xvalue 不能绑定到非常量左值引用
```

## 4. 值类别之间的关系与引用绑定规则

前面我们分别深入剖析了 lvalue、prvalue 和 xvalue 的定义、来源、属性和行为。现在，让我们把它们放在一起，看看它们之间的**关系**以及最核心的应用规则：**引用绑定**。

理解引用绑定规则，是真正“会用”值类别的标志。因为 C++ 编译器在决定一个表达式能不能绑定到某个引用时，**完全依赖其值类别**。

### 4.1 值类别的整体对比表格

| 属性 / 值类别      | `lvalue`                        | `prvalue`                      | `xvalue`                       |
|---------------------|---------------------------------|---------------------------------|---------------------------------|
| 有身份（identity）   | 是                              | 否                              | 是                              |
| 可取地址（&）？      | 是（通常）                      | 否                              | 是                              |
| 可被移动？           | 否（默认拷贝）                  | 是                              | 是                              |
| 生命周期            | 持久（由声明决定）              | 非常短暂（表达式结束销毁）      | 即将结束（full-expression 末尾）|
| 默认行为            | 拷贝                            | 拷贝消除或移动/拷贝   | 移动                            |
| 典型来源            | 变量、数组元素、*p、obj.member  | 字面量、临时对象、函数返回值    | std::move()、static_cast<T&&>   |
| 工程关键词          | 安全、持久、可修改              | 临时、高效、零开销优化          | 桥梁、显式资源转移              |

### 4.2 引用绑定规则一览

C++ 编译器根据表达式的值类别 + cv 限定 + 引用类型 来决定绑定是否合法：

| 引用类型          | `lvalue` | `prvalue` | `xvalue` | 备注与工程含义 |
|-------------------|--------|---------|--------|----------------|
| `T&` | ✅     | ❌      | ❌     | 只接受可修改的具名对象（最严格，防意外改临时量） |
| `const T&` | ✅     | ✅      | ✅     | 最万能的只读参数，绑定任何值类别，延长临时寿命 |
| `T&&` | ❌     | ✅      | ✅     | 非 const 右值引用，专为 `std::move` / 移动语义设计 |
| `const T&&` (常量右值引用) | ❌     | ✅ (const) | ✅ (const) | 极少使用，通常故意用来禁用移动或特殊约束 |
| `T&&` (模板中的转发引用) | ✅     | ✅      | ✅     | 转发引用（forwarding references），完美转发核心机制 |

**规则总结口诀**（快速记忆）：
- `T&`：只认左值
- const `T&`：全都要（最宽松，常用于只读参数）
- `T&&`：只认右值
- `T&&`（模板中）：左右值全认（完美转发）

### 4.3 典型绑定场景示例

```cpp
int x = 42;                      // x 是 lvalue

// 场景1：普通参数传递
void f1(int& r) {}               // 只能传 lvalue
f1(x);                           // OK
// f1(42);                       // 错误

// 场景2：常量引用（万能）
void f2(const int& cr) {}
f2(x);                           // OK
f2(42);                          // OK，临时延长生命周期

// 场景3：右值引用（移动专用）
void f3(int&& rr) {}
// f3(x);                        // 错误
f3(42);                          // OK，prvalue
f3(std::move(x));                // OK，xvalue

// 场景4：完美转发雏形（后续章节详解）
template<typename T>
void forwarder(T&& arg) {
    f3(std::forward<T>(arg));    // 保持原类别
}
forwarder(x);                    // 传给 f3 的是 xvalue
forwarder(42);                   // 传给 f3 的是 prvalue
```

## 5. 值类别相关的误区

前文我们已经系统梳理了 C++ 中的值类别体系及其在引用绑定中的精确规则。本节将从工程实践角度，剖析几个常见的误区，帮助读者避免在实际编码中踩坑。

### 5.1 一个常见误解：值类别 ≠ 左值 / 右值引用

一个在工程中极其常见、且极具迷惑性的错误认知是：

> “左值就是能绑定到 `T&`，右值就是能绑定到 `T&&`”

这是不准确的描述，请看下面这个例子：

```cpp
int&& rr = 1024; // OK
rr = 100;        // OK
```
这里 `1024` 是一个 `prvalue`，它能绑定到 `int&&`，这是符合规则的。 但是 `rr` 本身是一个 `lvalue`，因为它有名字，有身份。即使 `rr` 是通过右值引用声明的，它依然是一个 `lvalue`。

> 一旦一个右值被命名，它在表达式中就是 `lvalue`。

这也是为什么：

```cpp
void f(int&& x);

int&& rr = 1024;
// f(rr);         // 错误：rr 是 lvalue
f(std::move(rr)); // 正确：显式转换为 xvalue
```

### 5.2 “已移动对象”的语义本质

请看以下例子：

```cpp
std::string s = "hello";
auto t = std::move(s);
```

这里的 `std::move(s)` 将 `s` 转换为 `xvalue`，允许移动构造函数被调用。**但移动后，`s` 依然是一个 `lvalue`**，只是它的状态变成了“已移动”。

更准确的描述应该是：

> `std::move` 并不会移动任何东西，它只是改变表达式的值类别。

```cpp
std::move(s); // 一个 xvalue
```

真正发生移动的是：

- 移动构造函数
- 移动赋值运算符

而“已移动对象”的真实语义是：

> 对象仍然具有完整的 identity 和生命周期，但其资源处于“有效但未指定状态（valid but unspecified）”。
> 有关 `std::move` 的更多内容，请参考 [move ≠ 移动](/docs/中文版/move%20≠%20移动.md)章节。
