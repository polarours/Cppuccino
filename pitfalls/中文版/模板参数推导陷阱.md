# 模板参数推导陷阱

## 问题

模板参数推导可能失败或产生意外结果，特别是：
- 引用折叠规则
- 转发引用 vs 右值引用
- 非推导上下文

## 示例

```cpp
// 引用折叠的意外
template <typename T>
void f(T&& arg) {}  // 转发引用，不是右值引用

int x = 42;
f(x);      // T = int&, arg 是 int&（左值引用）
f(42);     // T = int, arg 是 int&&（右值引用）
```

```cpp
// 非推导上下文
template <typename T>
void g(std::vector<T> v) {}  // T 从 vector 元素类型推导

std::vector<int> v = {1, 2, 3};
g(v);     // OK：T = int

// 但这会失败：
g({1, 2, 3});  // 错误：无法从初始化列表推导 T
```

```cpp
// 推导指南的困惑
std::pair p(1, 2.0);  // C++17: T = pair<int, double>
// 但：
std::pair p{1, 2.0};  // 在某些编译器上 T = pair<double, double>！
```

```cpp
// SFINAE 并非在所有地方都有效
template <typename T>
auto toString(T value) -> decltype(std::to_string(value)) {
    return std::to_string(value);
}

// 对没有 std::to_string 重载的类型会失败
// toString(ComplexNumber{})  // 错误：没有匹配的重载
```

## 预防措施

- 理解引用折叠规则（T& + & = T&, T& + && = T&）
- 当需要值类型时使用 `std::decay_t`
- 对于有歧义的情况优先使用显式模板参数
- 使用 `std::enable_if` 或 concepts 进行 SFINAE 约束
- 使用 `static_assert` 或 `typeid` 测试推导
