# 线程安全的迷思

## 1. 引言

许多开发者认为使用 `const`、原子操作或简单的同步原语就能自动使代码线程安全。实际上，线程安全更加微妙，需要仔细设计。

## 2. 常见误解

### 2.1 "const 使其线程安全"

```cpp
class Config {
    std::string name_;
public:
    const std::string& name() const { return name_; }
};

// 两个线程读取同一个 Config 对象
Config config;
// 线程 1：config.name()  -- OK，const
// 线程 2：config.name()  -- OK，const
// 但如果一个线程在修改 config 而其他线程在读取呢？
```

**现实：** `const` 防止意外修改，但不提供线程安全。如果另一个线程修改对象，从 `const` 引用读取仍然是数据竞争。

### 2.2 "原子操作总是安全的"

```cpp
std::atomic<int> counter{0};

// 线程 1
counter++;  // 原子递增

// 线程 2
counter++;  // 原子递增

// 问题：这和 counter += 2 一样吗？不一定！
// 操作顺序可能是：T1 读取，T2 读取，T1 写入，T2 写入
```

**现实：** 原子操作对单个操作是安全的，但复合操作（读-修改-写序列）仍可能有竞态条件。

### 2.3 "每个对象一把锁就够了"

```cpp
class BankAccount {
    mutable std::mutex mtx_;
    int balance_;
public:
    void transfer(BankAccount& to, int amount) {
        std::lock_guard<std::mutex> lock(mtx_);
        balance_ -= amount;
        to.balance_ += amount;  // 死锁：另一个线程可能持有 to.mtx_
    }
};
```

**现实：** 锁定单个对象不能防止涉及多个对象的死锁。

## 3. 微妙的线程安全问题

### 3.1 非原子复合操作

```cpp
class Counter {
    int value_ = 0;
public:
    void increment() {
        value_++;  // 非原子：读取、递增、写入
    }
};

// 两个线程同时调用 increment()：
// 线程 1：读取 0，递增到 1，写入 1
// 线程 2：读取 0（在线程 1 写入之前），递增到 1，写入 1
// 结果：value_ 是 1，应该是 2
```

**修复：** 使用 `std::atomic<int>` 或适当的同步。

### 3.2 迭代器失效

```cpp
std::vector<int> vec = {1, 2, 3, 4, 5};

// 线程 1
for (auto it = vec.begin(); it != vec.end(); ++it) {
    // 线程 2 在这里修改 vec
    std::cout << *it << '\n';  // 迭代器可能无效
}
```

**修复：** 使用适当的同步或线程安全容器。

### 3.3 内存顺序

```cpp
std::atomic<bool> ready{false};
int data = 0;

// 线程 1
data = 42;
ready = true;  // 内存顺序：seq_cst（默认）

// 线程 2
while (!ready) {}
std::cout << data << '\n';  // 仍可能看到 0！
```

**现实：** 没有适当的内存顺序，编译器和 CPU 可能重排操作。

### 3.4 单线程库

```cpp
// 一些库不是线程安全的
class NonThreadSafeLib {
public:
    void process() {
        // 使用静态内部状态
        static int count = 0;
        count++;
    }
};

// 两个线程同时调用 process()：数据竞争！
```

## 4. 正确的同步模式

### 4.1 互斥锁

```cpp
class ThreadSafeCounter {
    mutable std::mutex mtx_;
    int value_ = 0;
public:
    void increment() {
        std::lock_guard<std::mutex> lock(mtx_);
        value_++;
    }
    int get() const {
        std::lock_guard<std::mutex> lock(mtx_);
        return value_;
    }
};
```

### 4.2 读写锁

```cpp
class ConcurrentMap {
    mutable std::shared_mutex mtx_;
    std::map<std::string, int> data_;
public:
    int get(const std::string& key) const {
        std::shared_lock<std::mutex> lock(mtx_);  // 允许多个读者
        return data_.at(key);
    }
    void set(const std::string& key, int value) {
        std::unique_lock<std::mutex> lock(mtx_);  // 独占访问
        data_[key] = value;
    }
};
```

### 4.3 无锁编程

```cpp
class LockFreeQueue {
    std::atomic<Node*> head_{nullptr};
public:
    void push(int value) {
        Node* node = new Node(value);
        node->next = head_.load();
        while (!head_.compare_exchange_weak(node->next, node)) {}
    }
};
```

## 5. 测试线程安全

### 5.1 压力测试

同时运行多个线程并检查：
- 数据竞争（使用 ThreadSanitizer）
- 死锁
- 正确性

### 5.2 形式化验证

对于关键代码，考虑使用形式化验证工具或证明。

## 6. 最佳实践

1. **记录线程安全** — 清晰声明哪些操作是线程安全的
2. **使用经过验证的模式** — 互斥锁、原子操作、线程局部存储
3. **最小化共享状态** — 最好的同步就是不共享
4. **避免过早优化** — 简单的锁通常足够快
5. **在负载下测试** — 线程错误通常只在高并发下出现
6. **使用工具** — ThreadSanitizer、helgrind、drd

## 7. 总结

- `const` 不保证线程安全
- 原子操作单独使用是安全的，但复合操作不是
- 正确的同步需要理解问题领域
- 清晰记录线程安全要求
- 在并发负载下彻底测试
