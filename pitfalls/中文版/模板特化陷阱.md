# 模板特化陷阱

## 引言

模板特化允许你为特定类型提供不同的实现。它很强大，但也有锋利的边角：

- **函数模板不能 *偏* 特化**——只能全特化。照着直觉写偏特化语法的程序员会直接撞上编译错误。
- **特化 `std` 里的模板**（少数允许用户自定义的 traits 除外）是**未定义行为**。
- 特化必须声明在**与主模板相同的命名空间**里、且在主模板可见之后，否则它会被静默地忽略，永远选不中。

这每一类都会导致要么编译不过，要么更糟——代码编过了，却从未使用你的特化。

## 问题

### 1. 函数模板的偏特化（无法编译）

```cpp
#include <iostream>

template <typename T>
void print(const T& v) { std::cout << v; }

// 错误：函数模板不允许偏特化
template <typename T>
void print<T*>(const T* v) { std::cout << "ptr:" << *v; }
```

### 2. 特化标准库容器（未定义行为）

```cpp
#include <vector>
struct MyType { int x; };

namespace std {
    // 未定义行为：不允许为你的类型特化 std 容器如 vector
    template <> class vector<MyType> { /* ... */ };
}
```

**为什么出错：**
- 编译器拒绝 `print<T*>`，因为语言干脆禁止函数模板的偏特化；请用重载替代。
- 为 `MyType` 特化 `std::vector` 是 UB：标准只允许特化少数 traits（`std::hash`、`std::numeric_limits`、`std::less` 等），且特化必须依赖于用户自定义类型。否则会产生不可预测的行为，并破坏 ABI 假设。

## 修复

### 1. 用重载替代函数模板偏特化

```cpp
#include <iostream>

template <typename T>
void print(const T& v) { std::cout << v; }

template <typename T>
void print(const T* v) { std::cout << "ptr:" << *v; }   // 重载，而非特化
```

重载决议会为指针参数选择指针版本，其余情况选择泛型版本——正是你想要的效果，而且合法。

### 2. 通过 traits / 你自己的类型来定制，绝不特化 `std` 容器

```cpp
#include <vector>
struct MyType { int x; };

// 给 MyType 自己的容器或 trait；不要去重开 namespace std
template <typename Alloc = std::allocator<MyType>>
using MyVec = std::vector<MyType, Alloc>;   // 别名，不是特化
```

如果你需要为用户自定义类型定制行为，定义自己的函数/类型，或 `std` 允许的 trait（例如特化 `std::hash<MyType>`），绝不要去特化容器。

## 最佳实践

- **要为「某些类型特化某个函数」时，写重载**，不要写偏特化。函数模板的全特化是允许的，但有了重载通常没必要。
- **绝不偏特化函数模板。** 这是不良形式的；修复办法永远是一个重载。
- **不要特化 `std` 模板**，除了明确允许的那些（`std::hash`、`std::numeric_limits`、`std::less`、比较 traits）。拿不准时，把逻辑放进你自己的 trait。
- **在主模板可见之后、同一命名空间内声明特化。** 编译器尚未见过的特化会被直接忽略——一个静默的、让人抓狂的 bug。
- **让类模板特化保持精简且刻意为之。** 当逻辑紧密相关时，优先用标签分发或 `if constexpr`，而非铺开一大堆特化。

## 总结

特化很容易让人伸手去用，也很容易用错。最常咬人的两个坑是：试图偏特化函数模板（改用重载），以及试图特化标准库容器（UB——用 trait 或你自己的类型）。把这两点搞对，特化就会成为一把精准的工具，而不是编译错误与静默错选的来源。
