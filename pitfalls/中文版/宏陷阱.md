# 宏陷阱

## 问题

C 预处理器宏是文本替换，不是代码。这导致了运算符优先级、
多次求值和作用域方面的微妙 bug。

## 示例

```cpp
// 经典：运算符优先级
#define SQUARE(x) x * x

int a = 3;
int result = SQUARE(a + 1);  // a + 1 * a + 1 = 3 + 3 + 1 = 7，不是 16！

// 修复：用括号包裹
#define SQUARE(x) ((x) * (x))
```

```cpp
// 多次求值
#define MAX(a, b) ((a) > (b) ? (a) : (b))

int x = 5;
int result = MAX(x++, 10);  // x 递增两次！如果 x 改变符号则是未定义行为
```

```cpp
// 作用域问题
#define DECLARE_INT(name) int name = 0;

void func() {
    DECLARE_INT(temp)  // 展开为：int temp = 0;
    DECLARE_INT(temp)  // 错误：重定义！
}
```

```cpp
// 字符串字面量问题
#define LOG(msg) std::cout << msg

LOG("Hello " "World");     // OK：字符串拼接
LOG(Hello World);           // 错误：未声明的标识符
LOG("Hello " + name);      // 错误：+ 不能与 "Hello " 一起使用
```

## 预防措施

- 始终用括号包裹宏参数
- 考虑使用内联函数或模板代替宏
- 多语句宏使用 `do { ... } while(0)`
- 用项目名前缀宏以避免冲突
- 如果宏是临时的，使用后 `#undef`
- 优先使用 `constexpr` 函数而非类函数宏
