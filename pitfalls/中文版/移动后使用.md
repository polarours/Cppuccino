# 移动后使用

## 问题

移动对象后，对象处于有效但未指定的状态。
在未重新初始化的情况下使用已移动的对象会导致未定义行为或意外结果。

## 示例

```cpp
std::string s1 = "Hello";
std::string s2 = std::move(s1);

// s1 现在处于有效但未指定的状态
// s2 = "Hello", s1 可能为空，也可能仍然有数据
std::cout << s1.size();  // 未定义行为或不可预测
```

```cpp
// 容器的常见错误
std::vector<int> v1 = {1, 2, 3};
std::vector<int> v2 = std::move(v1);

// 移动后 v1 在大多数实现中为空
// 但标准只保证"有效但未指定"
if (!v1.empty()) {
    // 在某些实现上可能会执行！
    process(v1);
}
```

## 为什么重要

移动后的状态是实现定义的。依赖特定的移动后值是非可移植的，
也是难以发现的 bug 来源。

## 预防措施

- 从不使用已移动的对象而不重新赋值
- 当你需要值并想移动时，优先使用 `std::exchange(obj, {})`
- 使用清晰的变量名：`original` vs `moved_to`
- 移动后将对象视为"空"或"已重置"
