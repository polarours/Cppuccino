# 内存序陷阱

## 问题

到处使用 `std::memory_order_seq_cst`（默认）是安全的但很慢。
错误使用 relaxed 顺序会导致微妙的数据竞争。

## 常见错误

```cpp
// 错误：relaxed store/load 对没有 happens-before 保证
std::atomic<int> flag{0};
std::atomic<int> data{0};

// 线程 1
data.store(42, std::memory_order_relaxed);
flag.store(1, std::memory_order_relaxed);

// 线程 2
while (flag.load(std::memory_order_relaxed) == 0) {}
std::cout << data.load(std::memory_order_relaxed);  // 可能打印 0！
```

## 正确用法

```cpp
// 线程 1：release 确保数据写入在 flag 之前可见
data.store(42, std::memory_order_release);
flag.store(1, std::memory_order_release);

// 线程 2：acquire 确保我们在 flag 之后看到数据
while (flag.load(std::memory_order_acquire) == 0) {}
std::cout << data.load(std::memory_order_acquire);  // 保证是 42
```

## 经验法则

- `relaxed`：无顺序（计数器、统计）
- `acquire/release`：线程间同步
- `seq_cst`：全序（有疑问时使用这个）

## 预防措施

- 从 `seq_cst` 开始，仅在性能分析后优化
- 记录哪个变量是同步点
- 复杂模式使用 `std::atomic_thread_fence`
- 使用 ThreadSanitizer（`-fsanitize=thread`）运行
