# 折叠表达式错误

## 引言

折叠表达式（C++17）让你用一行紧凑的代码把参数包「归约」到一个运算符上：

```cpp
template <typename... Ts>
auto sum(Ts... ts) { return (ts + ...); }   // 对所有实参求和
```

它极其简洁，但两个错误极其常见：

1. **忘了「空包对大多数运算符是非法的」。** 对 `+`、`*`、`&` 等运算符，`(ts + ...)` 在零实参时是编译错误（只有 `&&`、`||` 和逗号运算符有内建的空包行为）。
2. **括号放错位置 / 搞混一元与二元折叠语法**，产生「expected unqualified-id」或「pack must be expanded」之类错误。

## 问题

```cpp
template <typename... Ts>
auto sum(Ts... ts) {
    return (ts + ...);   // 当以 sum() 调用时出错：对 + 而言空包不合法
}
```

```cpp
// 另一个常犯的笔误：错误分组会把合法的折叠变成解析错误
template <typename... Ts>
void print_all(std::ostream& os, Ts... ts) {
    (os << ... << ts);    // 这其实合法，但 (os << ... << ts) 很容易被
                          // 误写成 os << (... << ts)，而后者不是折叠
}
```

**为什么出错：**
- 没有实参时，`(ts + ...)` 没有可供折叠的对象。标准规定这对 `+` 是非法的，所以 `sum()` 即使本意（「空的和为 0」）很自然，也编译不过。
- 折叠语法很严格：*一元*折叠是 `(pack op ...)` 或 `(... op pack)`；*二元*折叠是 `(pack op ... op init)` 或 `(init op ... op pack)`。少一个括号，编译器就看不到包展开，于是给出令人困惑的信息。

## 修复

### 1. 提供初始化值，让空包合法

```cpp
template <typename... Ts>
auto sum(Ts... ts) {
    // 带初始化值的二元折叠：空包 -> 0，合法
    return (ts + ... + 0);
}
```

现在 `sum()`、`sum(1)`、`sum(1, 2, 3)` 都能编译且行为正确。

### 2. 对流式 / 输出折叠使用正确的括号

```cpp
template <typename... Ts>
void print_all(std::ostream& os, Ts... ts) {
    (os << ... << ts);   // 正确：对包的一元折叠，从左到右
}
```

对于为了副作用而做的逗号折叠，包裹起来：`((std::cout << ts << '\n'), ...);`。

## 最佳实践

- **当函数可能以零实参调用、且运算符没有天然的空包值时（`+`、`*`、`&`、`|` 等），一定要加初始化值** `(pack op ... op init)`。`&&`/`||`/`,` 自带空包值，但显式写出更清晰。
- **记住两种形态。** 一元：`(... op pack)` / `(pack op ...)`。二元：`(pack op ... op init)`。包必须直接位于括号内。
- **括号即折叠。** `(std::cout << ... << ts)` 合法；`std::cout << (... << ts)` 不合法——整个折叠必须被括号包住。
- **为副作用优先用逗号折叠。** `((action(ts)), ...)` 会按顺序对每个元素执行 `action`，是用折叠做「遍历每个」的惯用法。
- **对非结合运算符留意结合性。** 对 `(... op pack)`，折叠自左向右展开；若你的运算符不满足结合性（例如 `-`），结果顺序很重要——请显式表达。

## 总结

折叠表达式是归约参数包最干净的方式，但必须对两条规则心存敬畏：空包对大多数运算符非法（所以要给初始化值），且包必须正确地位于折叠的括号之内（一元还是二元形态）。把这两条搞对，折叠就能用一行表意丰富的代码取代大段递归。
