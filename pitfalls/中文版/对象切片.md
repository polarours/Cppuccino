# 对象切片（Object Slicing）

## 1. 问题描述

对象切片指：派生类对象被按值复制/赋值到基类对象时，
仅基类子对象被保留，派生部分被丢弃。

该问题危险在于：

1. 代码通常可编译；
2. 运行常“看起来正常”；
3. 语义却悄然偏离设计意图。

在多态系统里，这往往直接破坏行为正确性。

---

## 2. 讨论边界

### 2.1 本文覆盖

1. 切片为何发生；
2. 常见触发场景；
3. 对行为与架构的影响；
4. 安全替代方案与治理清单。

### 2.2 本文不覆盖

本文并不反对继承本身。
重点是避免“值语义误用于运行时多态”。

---

## 3. 最小示例

```cpp
struct Base {
    virtual ~Base() = default;
    virtual const char* name() const { return "Base"; }
};

struct Derived : Base {
    const char* name() const override { return "Derived"; }
};

void print(Base b) { // 发生切片
    // b 是独立的 Base 对象
}
```

把 `Derived` 传给 `print` 时，会构造一个新的 `Base` 值对象。
派生状态不再存在于 `b` 中。

---

## 4. 根因（对象模型视角）

`Derived` = `Base` 子对象 + 派生扩展部分。
当目标类型是 `Base` 值对象时，
构造语义只能复制 `Base` 子对象。

因此切片并非“编译器偶然行为”，
而是值语义与继承层级的必然结果。

---

## 5. 静态类型与动态类型变化

切片前：

1. 静态类型可能是 `Base&`/`Base*`；
2. 动态类型可为 `Derived`。

切片后：

1. 对象静态类型为 `Base`；
2. 动态类型也成为 `Base`。

此时再期待派生覆写行为，逻辑上已不成立。

---

## 6. 高频触发场景

### 6.1 基类按值参数

```cpp
void log(Base b);
```

### 6.2 基类按值返回

```cpp
Base make_obj();
```

### 6.3 基类值容器

```cpp
std::vector<Base> xs;
xs.push_back(Derived{}); // 插入时切片
```

### 6.4 基类值赋值

```cpp
Base b;
Derived d;
b = d; // 派生信息丢失
```

---

## 7. 行为后果

切片会导致：

1. 派生状态丢失；
2. 虚分发结果偏离预期；
3. 业务逻辑隐性错误；
4. 测试覆盖不足时长期潜伏。

它不一定崩溃，但常导致“静默错误”。

---

## 8. 虚函数并不能挽救切片

虚分发依赖调用对象的动态类型。
切片后调用对象本身就是 `Base`，
因此调用 `Base` 版本是正确且必然的。

这不是“虚函数失效”，而是对象已不再是派生对象。

---

## 9. 安全接口形态

多态接口应使用间接访问：

1. `const Base&`：只读借用；
2. `Base&`：可变借用；
3. `Base*`：可空借用；
4. 智能指针：拥有语义。

```cpp
void print(const Base& b);
```

---

## 10. 容器设计建议

多态对象不应存入 `std::vector<Base>` 这类值容器。
推荐：

```cpp
std::vector<std::unique_ptr<Base>> items;
items.push_back(std::make_unique<Derived>());
```

这样可保留动态类型并明确所有权。

---

## 11. 所有权与生命周期

避免切片后，通常要引入引用/指针语义。
这要求同步澄清所有权：

1. 独占拥有优先 `std::unique_ptr`；
2. 共享拥有谨慎使用 `std::shared_ptr`；
3. 裸指针仅作观察者。

---

## 12. 多态基类拷贝策略

很多多态基类不应可拷贝。
可显式禁拷贝以阻断意外切片：

```cpp
struct Base {
    Base() = default;
    Base(const Base&) = delete;
    Base& operator=(const Base&) = delete;
    virtual ~Base() = default;
};
```

---

## 13. 需要“多态复制”时的 clone 模式

```cpp
#include <memory>

struct Base {
    virtual ~Base() = default;
    virtual std::unique_ptr<Base> clone() const = 0;
};

struct Derived : Base {
    std::unique_ptr<Base> clone() const override {
        return std::make_unique<Derived>(*this);
    }
};
```

通过虚接口复制可保留动态类型，不依赖基类值拷贝。

---

## 14. 工厂接口中的隐式切片

若工厂返回 `Base` 值：

```cpp
Base make();
```

即使内部创建 `Derived`，对外也会切片。
应改为返回 `std::unique_ptr<Base>` 或明确引用语义。

---

## 15. 工具函数中的隐蔽切片

模板/辅助函数也常引入切片：

```cpp
void consume(Base b);
```

若被广泛复用，切片问题会系统性扩散。
对“公共工具接口”尤其要审查参数形态。

---

## 16. 调试与日志代码也可能出错

“只是打印一下”这类辅助函数若按值接收基类，
同样会切片并误导排障。

日志 API 也应遵守多态接口规则。

---

## 17. 性能误区

有时会有人用基类按值传参来减少间接访问。
在多态场景下，这种“优化”通常是语义破坏。

正确做法是先保证语义，再做有证据的性能优化。

---

## 18. 工具与告警

建议启用可检测切片的告警/静态分析规则，关注：

1. 多态基类按值传参；
2. 派生对象写入基类值容器；
3. 可疑基类值拷贝构造路径。

工具能发现问题，但不能替代架构设计。

---

## 19. 常见反模式

1. 多态 API 设计为 `Base` 值参数；
2. 工厂返回 `Base` 值；
3. 使用 `std::vector<Base>` 存放派生对象；
4. 误以为切片后虚函数仍会到达派生实现；
5. 运行时多态目标与值语义接口并存。

---

## 20. 旧代码迁移建议

1. 搜索多态基类的按值参数/返回；
2. 改为引用/指针/智能指针接口；
3. 基类值容器迁移为拥有型多态容器；
4. 为多态复制引入 `clone`；
5. 为关键路径补充动态行为回归测试。

---

## 21. 代码评审清单

- [ ] 是否存在多态基类按值传参/返回？
- [ ] 是否存在基类值容器承载派生对象？
- [ ] 引入引用/指针后所有权是否清晰？
- [ ] 多态复制策略是否显式？
- [ ] CI 是否启用切片相关告警？
- [ ] 测试是否验证了动态分发语义？

若任一项不清晰，切片风险仍在。

---

## 22. 规避策略汇总

1. 多态接口使用引用/指针而非基类值；
2. 多态容器使用智能指针拥有对象；
3. 禁止多态基类隐式值拷贝（按需 `=delete`）；
4. 需要复制时使用 `clone` 协议；
5. 将切片视为语义错误，不是风格问题。

---

## 23. 总结

对象切片是“值语义 + 继承层级”组合下的确定结果。
它静默、可编译、危害大。

可靠工程规则可以一句话概括：

> 运行时多态依赖间接访问；
> 多态基类按值接口会破坏派生语义。

当团队统一执行这条规则，
可系统性消除一整类难排查的多态行为错误。
