# 返回局部对象的引用（或指针）

## 0. 先给边界与结论

本文讨论一个高频且危险的 C++ 生命周期陷阱：

- 返回自动存储期局部对象的引用；
- 返回自动存储期局部对象的指针；
- 返回间接指向局部对象的视图/迭代器。

核心结论：

1. 函数一旦返回，其自动局部对象已经析构。
2. 指向这些对象的引用/指针/视图随即悬垂。
3. 对悬垂句柄进行读写属于未定义行为（UB）。

工程结论：

- 默认优先按值返回；
- 只有在被引用对象寿命可证明长于调用侧使用期时才返回引用；
- 在 API 边界显式表达“所有权/借用”契约。

---

## 1. 最小错误示例

```cpp
const std::string& bad() {
    std::string s = "cpp";
    return s; // 函数返回后必然悬垂
}
```

错误机制：

- `s` 是自动存储期对象；
- `bad()` 退出时 `s` 生命周期结束；
- 返回引用指向的对象已不存在。

同类错误也常见于指针：

```cpp
const std::string* bad_ptr() {
    std::string s = "cpp";
    return &s; // 悬垂指针
}
```

以及“间接借用句柄”：

```cpp
std::string_view bad_view() {
    std::string s = "cpp";
    return std::string_view{s}; // 指向已失效缓冲区
}
```

---

## 2. 机制本质：存储期与生命周期不是同一个概念

需要严格区分两个层面：

1. **存储期**：内存从何而来、何时释放；
2. **对象生命周期**：对象何时构造为有效对象、何时析构终止。

对函数内自动局部对象：

- 存储与作用域绑定；
- 生命周期在作用域结束时终止；
- 析构在函数返回给调用方之前发生。

因此，调用方拿到“返回引用”时，所指对象已死亡。

一旦生命周期结束，继续通过原 glvalue/指针访问该对象即进入 UB。

---

## 3. 为什么“有时看起来没问题”

该问题的迷惑性很强，常见原因：

1. 栈上的旧字节短时间未被覆盖；
2. 优化级别改变执行与寄存器分配；
3. 不同编译器/平台呈现不同症状。

实际表现可能包括：

- 偶尔输出正确结果；
- 输出垃圾值；
- 间歇崩溃；
- 无报警的数据损坏。

以上全部都符合 UB 行为特征。

“Debug 正常、Release 出错”通常就是生命周期 UB 的典型信号。

## 4. 工程中常见变体

### 4.1 返回局部容器元素引用

```cpp
const int& bad_elem() {
    std::vector<int> v{1, 2, 3};
    return v[0]; // v 析构后元素随之失效
}
```

### 4.2 返回局部 `std::string` 的 `c_str()`

```cpp
const char* bad_cstr() {
    std::string s = "hello";
    return s.c_str(); // 指针在函数返回后失效
}
```

### 4.3 返回局部容器迭代器

```cpp
std::vector<int>::const_iterator bad_it() {
    std::vector<int> v{1, 2, 3};
    return v.begin(); // 迭代器悬垂
}
```

### 4.4 返回指向局部数组的 `std::span`

```cpp
std::span<const int> bad_span() {
    int a[] = {1, 2, 3};
    return std::span<const int>(a); // span 指向死亡对象
}
```

### 4.5 返回捕获局部引用的 lambda

```cpp
auto bad_lambda() {
    int x = 42;
    return [&]() { return x; }; // 闭包中引用悬垂
}
```

---

## 5. 正确模式

### 5.1 默认按值返回

```cpp
std::string good() {
    std::string s = "cpp";
    return s; // NRVO/移动，语义安全
}
```

优点：

- 所有权转移清晰；
- 不暴露借用生命周期风险；
- 现代编译器优化下通常高效。

### 5.2 仅在稳定宿主上返回引用

```cpp
class Config {
public:
    const std::string& name() const noexcept { return name_; }
private:
    std::string name_ = "service";
};
```

此模式安全前提：

- 引用指向 `*this` 的成员；
- 调用方保证 `Config` 实例在使用期间存活。

### 5.3 需要共享所有权时返回智能指针

```cpp
std::shared_ptr<std::string> make_name() {
    return std::make_shared<std::string>("cpp");
}
```

只在“确实要共享所有权”时使用。

### 5.4 由调用者提供输出对象

```cpp
void fill_name(std::string& out) {
    out = "cpp";
}
```

适用于热点路径中复用外部缓冲，避免隐式借用。

---

## 6. API 设计中的生命周期契约

在接口边界建议采用三分法：

1. **拥有型返回**：按值/智能指针返回；
2. **借用型返回**：引用/视图返回且必须声明宿主；
3. **禁止隐式宿主**：不返回依赖“隐藏临时对象”的借用句柄。

命名与文档建议：

- `get_*_copy()` 表示拥有拷贝；
- `*_view()` 表示借用视图；
- 写明前置条件：仅当 `X` 存活且未破坏约束时有效。

---

## 7. `static` 局部对象的区别

如下代码不会产生“局部对象返回悬垂”：

```cpp
const std::string& singleton_name() {
    static const std::string s = "cpp";
    return s; // 程序期存活
}
```

原因是 `static` 局部对象具备静态存储期。

但仍需权衡：

- 隐式全局状态；
- 跨翻译单元初始化/析构顺序；
- 可测试性与并发语义。

它是特定工具，不是“修复悬垂”的通用替代。

---

## 8. “按值返回很慢”是过时前提

大量错误接口来自对复制成本的过度焦虑。

现代 C++ 现实：

- 拷贝消除普遍；
- 移动构造对很多类型成本可控；
- 值语义显著降低生命周期复杂度。

建议遵循：

$$
	ext{可证明的生命周期正确性} > \text{未经测量的微优化猜测}
$$

先保证语义正确，再基于剖析数据优化。

---

## 9. 代码评审检查单

评审返回语句时逐项确认：

1. 返回类型是否为引用/指针/视图/迭代器？
2. 是否绑定到自动局部对象？
3. 是否绑定到临时对象的子对象或内部缓冲？
4. 宿主对象在调用侧是否可见且可证明存活？
5. 改为按值返回能否消除歧义？

高危红旗：

- `return local;`（函数返回 `T&`/`const T&`）；
- `return &local;`；
- `return local.c_str();`；
- `return std::string_view(local);`；
- 函数返回捕获 `[&]` 的闭包。

---

## 10. 工具与防线

可用防线：

1. 编译器告警：
   - 提高告警级别；
   - 在 CI 将生命周期告警升级为错误。
2. 运行期检测：
   - AddressSanitizer 可捕获大量悬垂访问。
3. 静态分析：
   - 逃逸分析/生命周期规则；
   - 自定义检查“返回局部对象地址或引用”。

工具无法覆盖全部路径，必须结合接口设计约束。

---

## 11. 遗留代码迁移策略

若历史接口已广泛返回危险借用：

1. 先分类函数：
   - 必然悬垂；
   - 条件安全；
   - 契约可证明安全。
2. 提供安全替代：
   - 新增按值返回重载；
   - 引入显式宿主参数。
3. 标记弃用旧接口。
4. 分阶段迁移调用点。
5. 在 sanitizer 下补回归测试。

推荐渐进式迁移，避免一次性大改动引入新风险。

---

## 12. 模式对照表

| 模式 | 安全性 | 更好替代 |
|---|---|---|
| 返回局部 `T` 的 `T&` | UB | 返回 `T` |
| 返回局部 `T` 的 `T*` | UB | 返回 `T` 或拥有型指针 |
| 返回局部 `string` 的 `string_view` | UB | 返回 `string` |
| 返回局部容器迭代器 | UB | 返回容器/值 |
| 返回稳定宿主成员引用 | 条件安全 | 明确文档化寿命前置条件 |

---

## 13. 关键结论回顾

1. 自动局部对象在函数退出时销毁。
2. 返回其引用/指针/视图会制造悬垂句柄。
3. 通过悬垂句柄访问是 UB。
4. 现代 C++ 中按值返回通常是最稳健默认方案。
5. 若必须借用，必须显式给出宿主与寿命约束，并确保可验证。

生命周期契约不是“文档修饰”，而是接口正确性的基础。
