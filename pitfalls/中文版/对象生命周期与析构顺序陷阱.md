# 对象生命周期与析构顺序陷阱

## 1. 引言

理解对象何时被创建和销毁是编写正确 C++ 代码的基础。违反生命周期规则会导致未定义行为，包括崩溃、数据损坏和难以复现的微妙错误。

## 2. 常见的生命周期问题

### 2.1 返回局部变量的引用

返回或存储局部变量的引用会创建悬垂引用：

```cpp
std::string& getGreeting() {
    std::string greeting = "Hello";
    return greeting;  // 错误：返回局部变量的引用
}

std::string& ref = getGreeting();  // 悬垂引用！
```

**修复：** 按值返回或使用堆分配。

### 2.2 delete 后使用指针

在删除指针指向的对象后使用该指针：

```cpp
int* p = new int(42);
delete p;
*p = 100;  // 未定义行为！

// 更糟糕：双重删除
delete p;  // 未定义行为！
```

**修复：** delete 后将指针设置为 `nullptr`，或使用智能指针。

### 2.3 迭代器失效

修改容器会使其迭代器失效：

```cpp
std::vector<int> v = {1, 2, 3, 4, 5};
for (auto it = v.begin(); it != v.end(); ++it) {
    if (*it == 3) {
        v.erase(it);  // 错误：it 现在无效
    }
}
```

**修复：** 使用 `erase` 返回的迭代器，或使用 erase-remove 惯用法。

## 3. 析构顺序规则

### 3.1 栈对象

栈对象按照构造的相反顺序销毁：

```cpp
{
    A a;  // 第一个构造
    B b;  // 第二个构造
    C c;  // 第三个构造
    // 销毁顺序：c, b, a（相反顺序）
}
```

### 3.2 类成员

成员按照声明的相反顺序销毁：

```cpp
class Widget {
    std::string name_;   // 第二个销毁
    std::vector<int> data_;  // 第一个销毁
};
```

### 3.3 基类

基类在派生类之后销毁：

```cpp
class Base {
public:
    ~Base() { std::cout << "Base destroyed\n"; }
};

class Derived : public Base {
public:
    ~Derived() { std::cout << "Derived destroyed\n"; }
};

Derived d;
// 输出：Derived destroyed, 然后 Base destroyed
```

## 4. 静态存储期

### 4.1 静态初始化顺序问题

不同翻译单元中的静态对象可能以不可预测的顺序初始化：

```cpp
// file1.cpp
extern int y;
int x = y + 1;  // 错误：y 可能尚未初始化

// file2.cpp
int y = 42;
```

**修复：** 使用"首次使用时构造"惯用法：

```cpp
int& getY() {
    static int y = 42;
    return y;
}
```

### 4.2 静态析构顺序

静态对象在翻译单元内按照构造的相反顺序销毁，但跨翻译单元的顺序是未定义的：

```cpp
// 这可能导致问题：
static std::ofstream log("app.log");
// log 可能在其他使用它的静态对象之前被销毁
```

## 5. 线程安全与生命周期

### 5.1 对象销毁时的竞争

在对象被销毁时从多个线程访问它：

```cpp
std::thread t1([&]() { obj.method(); });
std::thread t2([&]() { obj.~Object(); });  // 错误！
```

**修复：** 确保对象比所有访问它的线程存活更久。

### 5.2 线程局部存储

线程局部对象在线程退出时销毁：

```cpp
thread_local std::string name;
// name 在线程完成时被销毁
```

## 6. 智能指针生命周期

### 6.1 循环引用

```cpp
class Node {
    std::shared_ptr<Node> next;  // 强引用
};

auto a = std::make_shared<Node>();
auto b = std::make_shared<Node>();
a->next = b;
b->next = a;  // 循环引用：内存泄漏！
```

**修复：** 使用 `std::weak_ptr` 打破循环。

### 6.2 自定义删除器

```cpp
auto deleter = [](File* f) {
    std::cout << "Closing file\n";
    fclose(f);
};

std::unique_ptr<FILE, decltype(deleter)> file(fopen("test.txt", "r"), deleter);
```

## 7. 最佳实践

1. **使用 RAII** — 将资源生命周期绑定到对象生命周期
2. **使用智能指针** — 单一所有权优先使用 `unique_ptr`
3. **避免 raw new/delete** — 让容器和智能指针管理内存
4. **检查循环引用** — 使用 `weak_ptr` 打破循环
5. **理解析构顺序** — 编写可预测、结构良好的代码
6. **线程安全** — 确保对象比其线程存活更久
7. **静态对象** — 最小化翻译单元之间的依赖

## 8. 总结

- 对象按照构造的相反顺序销毁
- 悬垂引用和指针导致未定义行为
- 跨翻译单元的静态初始化顺序是未定义的
- 智能指针防止大多数生命周期问题，但有其自身的陷阱
- 设计 API 时始终考虑对象生命周期
