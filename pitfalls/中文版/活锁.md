# 活锁

## 1. 引言

**活锁（livelock）** 是指线程（或进程）不断根据彼此的状态做出改变，却**没有任何整体进展**的情况。和死锁不同，这些线程是*在运行*的——它们很忙、在消耗 CPU——但真正的工作永远完不成。

活锁有时被形容为"两个很礼貌的人不停给对方让路，结果谁都没能往前走"。

## 2. 问题

常见的成因是过于"礼貌"的带重试冲突处理：

```cpp
#include <atomic>
#include <thread>

std::atomic<bool> turn{false};  // 现在轮到谁前进？

void worker_a() {
    while (true) {
        if (!turn.load()) {
            turn.store(true);            // 礼貌地把机会让给 B
            std::this_thread::yield();
            continue;                    // 重试
        }
        do_work();
        turn.store(false);
        break;
    }
}

void worker_b() {
    while (true) {
        if (turn.load()) {
            turn.store(false);           // 礼貌地把机会让给 A
            std::this_thread::yield();
            continue;
        }
        do_work();
        turn.store(true);
        break;
    }
}
```

### 为什么出错

两个线程都在不断地检测到"冲突"，然后让出、把机会交给对方。每一次重试都把对方的进展清零。它们永远在空转、烧 CPU，却谁都没能执行到 `do_work()`。线程是活着、被调度的，但系统毫无进展。

## 3. 修复

### 3.1 随机退避

引入随机性，让线程不再时刻同步它们的重试：

```cpp
#include <chrono>
#include <random>

void worker() {
    std::mt19937 rng{std::random_device{}()};
    while (true) {
        if (try_acquire()) { do_work(); break; }
        // 指数 + 随机退避，打破对称性
        auto ms = std::uniform_int_distribution<int>(1, 10)(rng);
        std::this_thread::sleep_for(std::chrono::milliseconds(ms));
    }
}
```

### 3.2 单一协调者 / 明确的所有权

指定一个线程来做决策，或使用有清晰所有者的无锁队列，从根上消除这种对称的"礼貌"舞步。

### 3.3 使用合适的同步原语

通常一个 `std::mutex` 或条件变量就能彻底免去手写 yield-重试循环的必要。

## 4. 最佳实践

1. **不要只用 `yield()` 忙等**——要加入真正的退避或阻塞。
2. **随机化重试间隔**，打破竞争线程之间的对称性。
3. **优先用 mutex / condition_variable**，而不是手写重试循环。
4. **盯住 CPU 占用率**——100% 忙却不出结果，就是活锁的味道。

## 5. 总结

- 活锁 = 线程在跑却无进展（死锁 = 线程被阻塞）。
- 通常由对称的、过于礼貌的重试 / 让出逻辑引起。
- 用随机退避、单一所有权，或合适的原语来修复。
- CPU 占用高却不出结果，是关键症状。
